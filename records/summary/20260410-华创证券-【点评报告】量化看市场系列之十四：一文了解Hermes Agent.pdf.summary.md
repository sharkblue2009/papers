## 核心问题
这篇报告想回答：Hermes Agent 是什么、它和 OpenClaw / Claude Code 的差异在哪里、以及它如何通过内建的 Harness Engineering、记忆系统和多 Agent 协作机制提升长期任务执行能力。

## 方法 / 数据
- 以产品拆解和架构评测为主，结合安装与使用流程说明。
- 重点解析 Hermes 的学习循环、三层记忆、内置工具、delegate_task 协作机制和 Skill 修复流程。
- 参考开源产品文档与作者实测体验，不涉及传统量化回测。

## 关键发现
- Hermes 的核心差异是把“驾驭工程”从用户外置配置变成系统内建能力，并允许执行过程中自我生长与调整。
- 学习循环会在任务完成后自动触发，形成持续优化闭环。
- 记忆系统采用三层架构，底层基于 SQLite + FTS5，强调检索效率与上下文控制。
- delegate_task 可同时启动最多 3 个子 Agent，降低多 Agent 调度复杂度。
- Skill 修复采用 patch / 精准替换，便于快速迭代与局部修补。

- 可落地的“量化”结论更多体现在工程能力：支持多 Agent 协作、长任务持续运行、内建记忆与自动修复。
